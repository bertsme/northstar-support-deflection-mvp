### Team Working Agreement & Charter: Group 30

### 1. Project Scope & Selected Approaches

* **MVP Type**: Interactive Chatbot / Decision-Tree Flow
* **Target Ticket Categories**: 

  1. Order Status Automation ("Where is my order?")
  2. Returns & Refunds Automation ("How do I return this?")

### 2. Communication Channels & Core Norms

* **Primary Platform**: WhatsApp Group Chat
* **Response Windows**: Group members are expected to respond to direct tags and questions within 24 hours.
* **Meeting Attendance**: All members must attend scheduled syncs. If a member cannot make a session, they must notify the group at least 2 hours in advance.

### 3. Project Board & Commit Standards

* **Task Ownership**: No member will begin working on a sprint task unless their name is actively assigned to it on the GitHub project board.
* **Same-Day Updates**: Task statuses must be updated on the project board the same day the work is performed.
* **Commit Messaging Rule**: Every code change message must strictly follow the required format: <type>: <what changed> - <why it matters>. Generic titles are prohibited.

### 4. Conflict Resolution & Inactivity Escalation

* **The 2-Day Inactivity Rule**: If any team member shows zero visible activity on the shared GitHub repository or project board for 2 consecutive days without prior notice, the team will immediately trigger the formal escalation path to the sprint supervisor.
